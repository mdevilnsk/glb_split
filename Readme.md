# GLB Animation Editor

Браузерный редактор GLB-моделей: просмотр, нарезка анимаций на фрагменты, экспорт в ZIP. Всё работает **локально в браузере** — ни один файл не уходит на сервер.

![GLB Animation Editor](./docs/screenshot.png)

---

## ✨ Возможности

- 🎬 **3D-предпросмотр** модели прямо в браузере (Three.js + OrbitControls)
- ⏱ **Таймлайн с зумом** (1x–20x), скраббингом и перетаскиваемым Playhead
- ✂️ **Нарезка анимаций** на несколько фрагментов на одном таймлайне
- 🎯 **Магнит** при подгонке ползунков к Playhead и границам других фрагментов
- ▶️ **Проигрывание фрагмента** — от метки ◀ Start до ▶ End (пробел = Play/Pause)
- 💾 **Экспорт фрагментов** в ZIP — каждый фрагмент как отдельный `.glb`
- 📦 **Экспорт модели без анимаций** — чистый риг со скелетом
- 🔄 **Пресеты фрагментов** (JSON) — перенос нарезки на однотипные модели
- ⚡ **Скорость воспроизведения** от 0.1x до 2x

## 🚀 Быстрый старт

Из-за ES-модулей и `importmap` файлы нельзя открыть через `file://`. Нужен локальный сервер.

### Вариант 1: Python

```bash
cd glb-animation-editor
python -m http.server 8000
```

Откройте http://localhost:8000

### Вариант 2: Node.js

```bash
cd glb-animation-editor
npx serve
```

### Вариант 3: VS Code

Установите расширение **Live Server**, кликните правой кнопкой по `index.html` → **Open with Live Server**.

## 🎓 Как пользоваться

### 1. Загрузите модель

Перетащите `.glb`/`.gltf` в окно слева или нажмите на область загрузки.

### 2. Выберите анимацию

В панели справа под заголовком **«Анимации»** появится список. Кликните по нужной — она подгрузится в таймлайн, а модель примет позу первого кадра.

### 3. Настройте фрагмент

* **Playhead (красная линия)** — текущий кадр. Тяните мышкой или кликайте по треку.
* **Ползунки ◀ и ▶** (бирюзовые метки) — начало и конец выделения.
* **Магнит** — если подвести ползунок близко к Playhead или другому фрагменту, он «прилипнет».
* **Поля Начало / Конец** — можно ввести время вручную.
* **Имя файла** — как будет называться фрагмент при экспорте.
* Нажмите **«+ Добавить фрагмент»** — выделение превратится в фиолетовый блок на таймлайне.

### 4. Проиграйте фрагмент

Нажмите **▶** или **пробел**. Воспроизведение начнётся с метки ◀ Start и остановится на ▶ End.

### 5. Экспортируйте

* **«Экспортировать все в ZIP»** — архив с `.glb`-файлами по одному на каждый фрагмент.
* **«Скачать модель без анимаций»** — чистый риг со скелетом и мешами.

## 🎯 Пресеты (JSON)

Если у вас несколько моделей с **одинаковыми анимациями** (например, 20 вариантов ходьбы), можно один раз разметить фрагменты и применить их к другим файлам.

1. Загрузите первую модель, создайте фрагменты.
2. Нажмите **«⬇ Экспорт»** — скачается JSON с таймингами.
3. Загрузите вторую модель, выберите аналогичную анимацию.
4. Нажмите **«⬆ Импорт»** — фрагменты подгрузятся автоматически.
5. Если новая анимация короче — конец последнего фрагмента обрежется, вы увидите предупреждение.

**Формат JSON:**

```json
{
  "version": 1,
  "animationName": "Walk",
  "animationDuration": 2.4,
  "segments": [
    { "name": "Walk_Forward", "start": 0, "end": 0.8, "duration": 0.8 },
    { "name": "Walk_Backward", "start": 0.8, "end": 1.6, "duration": 0.8 }
  ]
}
```

## 🔧 Технические детали

### Стек

- **Three.js** — рендер и анимации
- **@gltf-transform/core** — чтение и запись GLB
- **JSZip** — упаковка результата
- Ванильный JS + ES-модули, без сборки

### Обработка интерполяции

При нарезке фрагмента мы фильтруем keyframes и **принудительно переводим интерполяцию в `LINEAR`**. Это сделано потому, что кубические танги (`CUBICSPLINE`) становятся невалидными после фильтрации — их нельзя частично сохранить, не пересчитав.

### Минимум 2 keyframes

glTF-спек требует минимум 2 keyframe на sampler. Если фильтр оставил один, мы дублируем его. Это спасает от «пустых» файлов.

### Клонирование документа

Используется round-trip (`writeBinary` → `readBinary`), а не `cloneDocument()` из `@gltf-transform/functions` — последний в v4 теряет sampler-ссылки при мутации анимаций.

---

## 🐛 Известные ограничения

- **CUBICSPLINE → LINEAR**: при нарезке качество кубической интерполяции теряется. Для игровых анимаций это обычно некритично, но если важна точность движения — не режьте через этот редактор.
- **Клонирование текстур**: каждая копия фрагмента содержит свои текстуры. При 20 фрагментах ZIP может весить в 20 раз больше.
- **Файлы > 80 МБ**: предупредит, но может тормозить. Для больших моделей используйте Node-версию.
